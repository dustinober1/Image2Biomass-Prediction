  <name>Task 1: Create ExperimentOrganizer class for grouping and tagging</name>
  <files>mlflow_tracking/organizer.py</files>
  <action>
Create mlflow_tracking/organizer.py with ExperimentOrganizer class that provides:

1. **Constructor**: Initialize with MLflow client (from config)
   - Accepts optional tracking_uri parameter
   - Sets up MlflowClient instance

2. **create_group(group_name: str, tags: Optional[dict] = None) -> str**
   - Creates MLflow experiment (group) with specified name
   - Optional tags to describe the group (e.g., {"purpose": "ablation-study"})
   - Returns experiment_id
   - Uses mlflow.create_experiment() if group doesn't exist
   - Uses mlflow.get_experiment_by_name() to check existence first

3. **add_tags_to_run(run_id: str, tags: dict) -> None**
   - Adds tags to existing run using mlflow_client.set_tag()
   - Accepts dictionary of tag key-value pairs
   - Useful for post-hoc organization (e.g., marking successful runs)

4. **search_runs(
    experiment_ids: Optional[list[str]] = None,
    filter_string: str = "",
    max_results: int = 1000,
    order_by: list[str] = None
  ) -> list[dict]**
   - Searches experiments using mlflow.search_runs()
   - Supports MLflow filter syntax:
     - Metrics: "metrics.val_rmse < 10.0"
     - Params: "params.model_type = 'random_forest'"
     - Tags: "tags.status = 'completed'"
     - Combined: "params.model_type = 'xgboost' and metrics.test_rmse < 15.0"
   - Returns list of simplified run dicts with: run_id, experiment_id, params, metrics, tags, start_time, status
   - Order by specified metrics (e.g., ["metrics.val_rmse ASC"])
   - Defaults to returning all experiments if no filter provided

5. **list_groups() -> list[dict]**
   - Returns all experiments (groups) using mlflow.list_experiments()
   - Each dict contains: experiment_id, name, artifact_location, tags, creation_time
   - Useful for discovering available groups

6. **get_best_runs(
    group_name: str,
    metric_name: str,
    top_k: int = 5
  ) -> list[dict]**
   - Finds top K runs in a group by specified metric
   - Uses search_runs() with ordering
   - Returns sorted list of run dictionaries

Design patterns:
- Use mlflow.tracking.MlflowClient for all operations
- Validate inputs (non-empty strings, positive integers)
- Return simplified dicts (not MLflow objects) for ease of use
- Follow existing patterns from tracker.py (error messages, type hints)

Import requirements:
- from mlflow.tracking import MlflowClient
- from mlflow_tracking.config import MLFLOW_TRACKING_URI
- from typing import Optional, List, Dict

Do NOT:
- Don't create custom storage - use MLflow's built-in experiment/run model
- Don't reimplement search - use mlflow.search_runs() with filter strings
- Don't add web UI - MLflow UI already exists, just document how to use it

<task type="auto">
  <name>Task 2: Extend ExperimentTracker with tagging methods</name>
  <files>mlflow_tracking/tracker.py</files>
  <action>
Update mlflow_tracking/tracker.py to add convenience methods for tagging:

1. **add_tags(tags: dict) -> None**
   - Adds tags to the currently active run
   - Wrapper around mlflow.set_tags() for consistency with our SDK
   - Raises RuntimeError if no active run
   - Example: tracker.add_tags({"model_type": "random_forest", "phase": "feature_ablation"})

2. **set_group(group_name: str, create_if_missing: bool = True) -> None**
   - Sets the MLflow experiment (group) for the current run
   - If create_if_missing=True, creates the experiment if it doesn't exist
   - Uses mlflow.set_experiment() internally
   - Must be called BEFORE start_run() to take effect
   - Useful for organizing runs into logical groups
   - Example: tracker.set_group("ablation-studies")

3. **get_run_id() -> str**
   - Returns the active run ID
   - Useful for passing to ExperimentOrganizer.search_runs() or add_tags_to_run()
   - Raises RuntimeError if no active run

Implementation notes:
- Add type hints for all new methods
- Follow existing error handling patterns (RuntimeError with clear messages)
- Add docstrings with examples
- Don't break existing API - all additions are backward compatible

Location:
- Add methods after existing log_environment() method (around line 154)
- Maintain consistent code style with existing methods
  </action>
